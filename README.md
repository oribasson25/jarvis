# סוכן וואטסאפ – חבר AI בקבוצה

מערכת שמחברת מספר וואטסאפ ייעודי ל-Claude. מצרפים את המספר לקבוצה כמו כל חבר, והוא קורא את השיחה ומגיב לפי ההגדרות שקובעים בדשבורד. רצה כולה על Vercel.

## הקמה על Vercel (נדרש Pro)

1. **מסד נתונים**: בפרויקט ב-Vercel: Storage ← Create Database ← **Upstash for Redis** (מסלול חינמי) ← לחבר לפרויקט. זה מוסיף לבד את משתני `KV_REST_API_URL` ו-`KV_REST_API_TOKEN`.
2. **משתני סביבה** (Settings ← Environment Variables, ל-Production):
   - `DASHBOARD_PASSWORD`: הסיסמה לדשבורד. **חובה**, בלעדיה הדשבורד לא נפתח.
   - `CRON_SECRET`: מחרוזת אקראית ארוכה. מגינה על הפונקציה שמחזיקה את החיבור.
   - `ANTHROPIC_API_KEY`: אופציונלי, אפשר גם להדביק בדשבורד.
3. **Redeploy** (Deployments ← הפריסה האחרונה ← Redeploy), כדי שהמשתנים ייכנסו לתוקף.
4. **נכנסים לאתר** עם הסיסמה, מדביקים מפתח Claude, וסורקים את ה-QR מהטלפון של הסוכן (WhatsApp Business ← מכשירים מקושרים ← קישור מכשיר).
5. **מצרפים את המספר לקבוצה**. היא תופיע ב"קבוצות ושיחות", ושם אפשר להגדיר לה מצב והנחיות משלה. בודקים ב"מגרש ניסויים" לפני שמשחררים אותו לחברים.

## איך זה רץ על Vercel

וואטסאפ דורש חיבור פתוח כל הזמן, ופונקציה ב-Vercel יכולה לרוץ עד 800 שניות. לכן:

- `api/worker.js` מחזיק את החיבור כ-12 דקות, ואז מסיים את התגובות הפתוחות, שומר את מפתחות החיבור ב-Redis ומפעיל את ההרצה הבאה. הודעות שמגיעות בשניות של ההחלפה נשמרות אצל וואטסאפ ומגיעות לחיבור הבא.
- Cron של Vercel קורא ל-`api/worker.js` כל דקה, כגיבוי: אם השרשרת נשברה, החיבור חוזר תוך דקה-שתיים.
- נעילה ב-Redis מבטיחה שרק הרצה אחת מחוברת לוואטסאפ בכל רגע.
- כשאין מספר מקושר, הסוכן מציג QR רק כשהדשבורד פתוח, כדי לא לבזבז משאבים.
- `api/app.js` הוא ה-API של הדשבורד (`/api/v1/*`), והדף עצמו מוגש מ-`public/`.

## מצבי תגובה

| מצב | מה קורה |
|---|---|
| כבוי | קורא ושומר הודעות, לא כותב |
| רק כשפונים אליו (ברירת מחדל לקבוצות) | מתייגים אותו, קוראים לו בשם/מילת קריאה, או עונים להודעה שלו |
| מחליט לבד | קורא הכל ומחליט מתי להשתתף, לפי "רמת מעורבות" |
| מגיב לכל הודעה | מגיב על כל רצף הודעות |

הסוכן יכול לענות (גם בציטוט), להגיב באימוג׳י, או לשתוק. רצף הודעות מהיר נאסף לתגובה אחת. בשעות שקט הוא עונה רק כשפונים אליו, ויש מגבלת פעולות בשעה לכל שיחה.

## קבצים

- `src/worker.js`: הרצה אחת של החיבור (נעילה, פקודות מהדשבורד, החלפה מסודרת)
- `src/whatsapp.js`: חיבור כמכשיר מקושר דרך [Baileys](https://github.com/WhiskeySockets/Baileys)
- `src/auth-state.js`: מפתחות החיבור לוואטסאפ ב-Redis
- `src/router.js`: שמירת הודעות, החלטה מתי לענות, איחוד רצפים
- `src/agent.js`: הפרומפט והקריאה ל-Claude (JSON: `reply` / `react` / `silent`)
- `src/db.js`, `src/redis.js`: אחסון ב-Upstash Redis
- `src/control.js`: תיאום בין הדשבורד להרצה שמחזיקה את החיבור
- `src/app.js` + `public/`: הדשבורד

## עלויות

- **Vercel Pro**: ‏20$ לחודש, כולל 20$ קרדיט. הפונקציה שמחזיקה את החיבור רצה כל הזמן (בערך 1,460 GB-שעות בחודש). הפונקציות רצות באזור `iad1` (מזרח ארה"ב), מהזולים, כך שזה אמור להיכנס בערך בקרדיט.
- **Upstash**: המסלול החינמי הוא 500 אלף פקודות בחודש. ההחזקה של החיבור לבדה צורכת בערך 200 אלף, והשאר תלוי בכמות ההודעות. מעבר לזה: 0.2$ לכל 100 אלף.
- **Claude**: לפי שימוש. ברירת המחדל Opus 5.5 עם עומק חשיבה נמוך. במצב "מחליט לבד" בקבוצה פעילה כדאי לשקול Haiku.

## פיתוח מקומי

```bash
npm install
npm start
```

בלי משתני Upstash הכל נשמר בזיכרון ונמחק בכל הפעלה. כדי לעבוד מול אותו מסד נתונים של Vercel: `vercel env pull .env`. אם הסוכן כבר מחובר ב-Vercel, ההרצה המקומית רק תחכה לתורה, כי הנעילה לא תיתן לשתי הרצות להתחבר במקביל.

## שימו לב

- **זה לא ממשק רשמי של וואטסאפ.** יש סיכון שהמספר ייחסם, לכן משתמשים במספר נפרד ולא מציפים בהודעות. ההתחברות מחדש כל 12 דקות לא נבדקה מבחינת חסימה.
- הטלפון של הסוכן צריך להתחבר לאינטרנט לפחות פעם בשבועיים, אחרת המכשיר המקושר מתנתק.
- תמונות, הקלטות וסטיקרים מגיעים לסוכן רק כתיאור ("[תמונה] + כיתוב").
